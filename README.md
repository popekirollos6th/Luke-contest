# مسابقة إنجيل لوقا 1–6 مع Supabase ولوحة نتائج

## الملفات
- `index.html`: المسابقة بالعربية، 20 سؤالًا عشوائيًا، 20 ثانية لكل سؤال.
- `admin.html`: لوحة المنسق وتصدير CSV.
- `supabase-config.js`: ضع فيه Project URL والمفتاح العام (publishable/anon) فقط.
- `supabase_setup.sql`: الجداول ودوال حجز المحاولة وإنهائها وسياسة قراءة النتائج للمنسق.

## الإعداد الأول مرة واحدة
1. ملف `supabase-config.js` مُعدّ بالفعل برابط مشروعك والمفتاح العام الذي أرسلته.
2. افتح مشروع Supabase ثم SQL Editor، واستخدم النسخة المصححة من `supabase_setup.sql` داخل الحزمة الأخيرة، والصق محتواها كاملًا ثم اضغط Run. لو ظهر الخطأ السابق، لا تشغّل السطر القديم الذي يبدأ بـ `grant execute` قبل إنشاء الدوال؛ النسخة المصححة ترتب ذلك تلقائيًا. هذا ينشئ الجداول ودوال تسجيل المحاولة وسياسات قراءة النتائج.
3. من Authentication → Users أنشئ حسابًا للمنسق باستخدام البريد وكلمة المرور.
4. في SQL Editor نفّذ الأمر التالي مع استبدال البريد ببريد المنسق:

```sql
insert into public.quiz_admins(user_id)
select id from auth.users where email = 'ADMIN_EMAIL_HERE'
on conflict do nothing;
```

5. ارفع كل الملفات إلى جذر مستودع GitHub Pages. افتح رابط الموقع للمشاركين، ولوحة النتائج من `admin.html` في نفس رابط الموقع.

## ملاحظات أمان مهمة
- مفتاح `anon/publishable` مصمم للاستخدام بالمتصفح، لكن لا تستخدم مفتاح `service_role` مطلقًا.
- حجز الاسم مركزي وفريد في قاعدة البيانات. النتيجة الحالية تُحسب في المتصفح ثم تُرسل عبر RPC؛ هذا MVP مناسب للتجربة لكنه ليس مقاومًا لمحاولات التلاعب المتعمدة. للحماية القوية يجب نقل بنك الأسئلة والتصحيح إلى Edge Function والتحقق من الوقت على الخادم.
- الاسم الثلاثي ليس إثبات هوية قويًا؛ شخصان بالاسم نفسه سيتعارضان. يمكن لاحقًا استخدام رقم تسجيل خاص أو دعوة فريدة إذا رغبتِ، من دون عرضه ككود مشارك.
- راجعوا صياغة الأسئلة والاقتباسات مع الترجمة الكتابية المعتمدة قبل المسابقة الرسمية.


## حالة الربط
الملفات مهيأة بعنوان مشروع Supabase والمفتاح العام المرسل. الاتصال لن يعمل حتى تشغّل `supabase_setup.sql` في SQL Editor وتضيف حساب المنسق إلى `quiz_admins` كما هو موضح أعلاه. لم يتم تنفيذ تغييرات داخل حساب Supabase من هنا.
